# 信源扩充与 Vercel 采集改造

## 目标与边界

按已确认的全球与中国均衡名单扩充十个分类；保留现有禁用来源。X 使用官方 API，Tibo 为 `@thsottiaux`，新增名单保留身份核对和任职状态说明。凭据缺失时不发出 X 付费读取请求。

在最新主分支的全信源刷新基础上，将采集并发提高到 50。轮询表示定时再次检查，并不要求串行。保持当前两小时 Cron 频率，先改变单轮吞吐；后续可单独调整时间间隔。正常直连与 RSS 优先，Firecrawl 仅补充失败或未发现近期候选的来源。并发池持续补位，不等待一批全部结束。

## 实施约定

1. `NewsSource.xUsername` 标识官方 X API 入口；`SourceSection.feedUrl` 区分订阅入口和供读者访问的来源页面。RSS 入口须明确授权主机，候选文章仍受原来源的主机和路径约束。
2. 默认 50 个来源任务；对直接 HTTP 请求、Firecrawl 和翻译分别限流，避免两条采集路径叠加成无界并发。保留单请求超时和整轮截止时间。
3. Vercel 的 `/api/cron`、`/api/refresh` 使用 300 秒时限，默认采集预算 240 秒。Supabase Cron 请求等待时间与刷新租约同步调整；持续续租并在失去租约后停止提交。变更采用新增数据库迁移，不改写历史迁移。
4. X 使用用户时间线 API，排除转发和回复，保存用户 ID、增量 `since_id` 及未完成分页进度。游标随候选与来源结果原子提交；失败不跳过尚未持久化的帖子。X 配置与未来服务器常驻流共用。
5. 采集继续经共享服务和 Node 入口运行，网站读取已发布结果。此次不更改前端、已合并的语义去重、报道准入或发布不变量。

## 验证与交付

验证全来源覆盖、50 并发补位、RSS 优先与失败回退、截止时间、续租失败、X 分页和重复防止；运行单元、集成、构建及可用的数据库检查。只测试公开免密信源，不调用付费 X API。更新分类确认表及运行文档，提交并创建 PR，生产部署与付费读取状态分别说明。
